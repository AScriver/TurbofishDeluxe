# M1 window experiments 01–02

**Result:** The Rust interaction loop executed at normal speed, but these runs did not pass full acceptance. Run01 exposed an inverted camera; run02 confirmed its correction, then failed when a telemetry reader prevented file replacement. Preserve both as historical evidence. Original-game behavior/fidelity remains unverified.

## Failure experiment and follow-up

A fresh run of frozen run02 without a reader exited0 and wrote save/final receipts. A controlled read handle with `FileShare.ReadWrite` (no Delete), held for2s, reproduced exit1/AccessDenied at the next snapshot rename, leaving the previous complete JSON and a newer pending file. This establishes that a reader could abort gameplay; it does not identify which reader caused run02's contention.

The follow-up preserves completed snapshots and retries optional telemetry publication after contention, without blocking ticks or hiding critical save errors. Facing and telemetry changes require new identified runtime evidence. Unit tests check atomic complete-file replacement and resumed-state equivalence; they do not establish game fidelity.
