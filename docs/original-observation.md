# Original-game observation boundary

The owned install is identified in [STATUS](../STATUS.md); it has been read and analyzed, but the retail executable has **not been launched** during this work. Static binary findings and Rust window runs remain distinct from an original-game comparison.

A read-only W1 study found that an alternate working directory alone does not isolate retail state. Framework `SexyAppBase.cpp:6058–6074,1890–1923` opens/creates HKCU product keys and writes InProgress before configuring the save root. `Common.cpp:683–705` obtains COMMON_APPDATA through SHGetFolderPath; `WinFishApp.cpp:385–389` creates userdata there. Profile, highscore and shutdown callers write outside the install. `-changedir` controls the working directory, with no supported save/registry override established. Product mutex identity is also independent of an executable rename.

Other source callers include D3DTester direct registry writes, the music interface's mixer settings, fullscreen display changes and screensaver settings. These are **secondary-source-derived possible side effects**, not evidence that this Windows build executed them. A copied executable, environment variables or a launcher-side RegOverridePredefKey do not establish process-wide containment: [SHGetFolderPath](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shgetfolderpatha) uses known folders, and [RegOverridePredefKey](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-regoverridepredefkey) applies to the calling process.

On this machine, WindowsSandbox.exe was absent on 2026-10-08. No sandbox feature was installed or enabled, no original process was attached, and no retail saves/registry were changed.
