## Ownership and implementation decision

Extend the existing Alien kind for Destructor. Keep separate serializable Board-owned missiles with stable IDs/target IDs; derive the reverse assignment from the list instead of persisting duplicate backlinks. Keep a bounded Rufus actor following existing modules. Register each launch before the next target search and before the reload RNG draw. The Board owns all prey detachment paths, staged impact death/corpse, missile effects, one Alien reward and occupied→empty battle completion. Launched missiles survive their launching Alien. A missile must never retain a dangling prey reference or clear another missile's assignment; normal starvation/poison/consumption/bite synchronously detaches its missile. Invalid current saves fail validation. Follow current-save scope in requirements; no new legacy migration.

Use an explicit missile phase after the Alien transaction and before pets, including newly launched missiles. This deterministic choice is not recovered WidgetManager order; each missile resolves fresh prey state after earlier removals. Split Alien defeat from battle completion, preserving pending death after Rufus contact. Vert's primary gate remains Alien/Bilaterus membership; wave countdown/completion also include missiles. Keep survival's existing beginning-of-update check: a last fish killed by a missile during object updates triggers Game Over next update. Detailed static review/source hashes are retained privately in `.scratch/runtime/architect/a24-ownership-review.md`; no original or runtime missile experiment was performed.

Rufus rendering uses the owned sheet and exact stationary/moving row choice; missiles use owned directional frames. General-purpose tracker music is a separate [audio](audio.md) increment; do not couple its private decoder adoption to actor state. Unrecovered trails/particles/RNG/source sound variation remain explicit gaps.
